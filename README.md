# Balance — личные финансы

Система управления личными финансами: последовательные цели (предложение, свадьба, автомобиль), распределение зарплаты, дневной лимит из доступного остатка и резерва, план погашения долга. Mobile-first приложение: Overview, операции и их редактирование, категории, месячная аналитика, cashflow, savings rate, повторяющиеся платежи и бюджеты. Интерфейс на русском, без сторонних шрифтов и трекеров. Сервер: Node.js / Vercel Functions. Постоянное хранилище: Neon PostgreSQL. Локально можно работать с JSON.

## Локальный запуск

Нужен Node.js 22 или новее.

1. `npm install`
2. Скопируйте `.env.example` в `.env`.
3. `npm run password -- 'ваш-длинный-уникальный-пароль'` — вставьте результат в `PASSWORD_HASH`. Пароль не хранится открытым текстом. Для `SESSION_SECRET` используйте результат `openssl rand -hex 32`.
4. Оставьте `LOCAL_DATA=1`. `npm run seed` импортирует приложенный `transactions.private.json` в приватное локальное хранилище.
5. `npm run dev`, откройте http://localhost:3000 и войдите своим паролем.
6. `npm test` и `npm run build` проверяют логику и создают публичную сборку.

## GitHub и Vercel

1. Создайте репозиторий и загрузите содержимое этой папки. `.gitignore` исключает выписку, личные транзакции, отчёт, локальную базу и секреты. **Не загружайте весь ZIP через веб-интерфейс GitHub:** сначала распакуйте и используйте Git, который учитывает `.gitignore`.
2. Создайте PostgreSQL в Neon (напрямую или через Marketplace Vercel), получите `DATABASE_URL`.
3. Локально в `.env` задайте `DATABASE_URL`, `LOCAL_DATA=0`. Запустите `npm run seed`: создаются таблицы и импортируются 956 записей; повторный импорт не дублирует и не перезаписывает отредактированные записи. Сам файл выписки не публикуется.
4. В Vercel импортируйте репозиторий. Framework: Other. Build: `npm run build`; Output: `dist`. Функция находится в `api/app.js`.
5. В Environment Variables добавьте `DATABASE_URL`, `PASSWORD_HASH`, `SESSION_SECRET` (минимум 32 символа). `LOCAL_DATA` не добавляйте: файловый режим запрещён в Vercel. Задавайте секреты отдельно для Production и Preview. Для Preview лучше отдельная база.
6. Deploy. Без секретов приложение отказывает в доступе; без подготовки БД вернёт понятную ошибку. Проверьте вход, сохранение операции и сохранение бюджета после обновления страницы.
7. Settings → Domains → Add Domain. Введите собственный домен и установите у регистратора DNS-записи, которые покажет Vercel. После проверки DNS дождитесь HTTPS-сертификата. Авторизация действует и на собственном домене.

Документация: [Vercel Node.js](https://vercel.com/docs/functions/runtimes/node-js), [домены Vercel](https://vercel.com/docs/domains/working-with-domains/add-a-domain), [Neon](https://neon.com/docs/serverless/serverless-driver).

## Защита и хранение

Все финансовые данные выдаются только авторизованной серверной функцией, никогда не включаются в публичную сборку. В браузер до входа попадает только оболочка. Пароль — scrypt; сессия подписана HMAC, живёт 24 часа; cookie HttpOnly, SameSite=Strict и Secure в Vercel. Изменения проверяют Origin. Ограничение входа — 10 попыток за 15 минут по IP, в PostgreSQL; параметры SQL передаются безопасно. Для отзыва всех сессий смените SESSION_SECRET. Это личное приложение для одного владельца, без регистрации и восстановления пароля через почту.

Серверный импорт и локальная база содержат финансовые данные — храните их приватно. Источник содержит персональные сведения; паспорт и номер счёта не перенесены, телефоны скрыты. Имена контрагентов в описаниях сохранены для проверки. База данных содержит приватные записи: используйте резервные копии Neon.

## Методика

Деньги хранятся целым числом копеек. Все 956 строк сохранены, включая исключённые из аналитики. Дата аналитики — дата операции, не обработки. Суммы сверены с обеими частями банковской выписки. `page` — физическая страница PDF, `posted` — дата обработки. Не удаляем похожие покупки автоматически: они могут быть разными.

`internal` — переводы владельцу с совпадающим именем, явные внутренние переводы и перенос ЭДС. `investment` — покупка/погашение паёв. `debt` — основной долг, отдельно от расходов потребления; проценты входят в расходы. `refund` уменьшает расходы, а не увеличивает доход. Возвраты без однозначной категории оставлены отдельно. Внешние переводы физлицам включены в денежные расходы с флагом проверки; это могут быть займы или компенсации. Внешние поступления не приравнены к зарплате. Категоризация эвристическая, неизвестные продавцы оставлены в «Другое».

Личный график зарплаты хранится в settings.private.json и импортируется в защищённое хранилище вместе с операциями. Это информация владельца, не дополнительные операции. Savings rate на экране рассчитан по фактическим внешним поступлениям этого счёта и включает основной долг в отток; показатель не равен норме накоплений по всем банкам.

Сентябрь заканчивается 23-м числом. Средние расходы и оценка накоплений основаны на июле–августе, двух полных месяцах. Текст исходного отчёта и базовые рекомендации — снимок анализа выписки; новые операции обновляют числовую аналитику и бюджеты, но не переписывают текст рекомендаций. Повторяемость не доказывает автосписание, отмена подписок выполняется у продавца. Синхронизация с банком не подключена.

## Проверки перед реальным запуском

Локально проверены сверка выписки, расчёт возвратов/долга, подпись сессии, API входа/записи и сборка. Облачный импорт, подключение реальной Neon БД, Vercel и DNS требуют ваших аккаунтов и проверяются после настройки. Проект подготовлен для публикации, автоматически не опубликован.

План жизни требует будущего бюджета жизни и уже накопленных сумм. Неизвестные поля остаются пустыми; неподтверждённые сроки не выдумываются. Прогноз без доходности и инфляции, с постоянной зарплатой и расходами. Цели финансируются последовательно. Долг Т-Банка не уменьшается от внутренних переводов; его актуальный остаток проверяется отдельно.
